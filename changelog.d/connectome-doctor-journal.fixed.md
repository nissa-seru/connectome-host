- `scripts/connectome-doctor` reads a unit's output from its journal when the unit has no log file, as `connectome service install`'s systemd units don't, and when the only `logs/agent.log` there predates the unit's start: its recent failures, its last delivery and its live gate dump. Before, it said "none found" in a log file that wasn't there or was left from before. It reads `logs/failures.log` for either, and says when the journal, the file it reads the host's lines from or `logs/failures.log` can't be read, rather than finding nothing in it.
- `scripts/connectome-doctor` reads the file a unit sends its stderr to, from systemd's own `StandardError` (or `StandardOutput`, when stderr inherits it) and the unit's last such line, drop-ins included, with `%h`, `%t`, `%u`, `%U` and `%%` expanded from the ladder's own home, runtime directory and user; a path with another specifier is a finding, and is read with that specifier left as written. Before, it took the first file redirect in the unit file's text, a commented one included, for both streams.
- `scripts/connectome-doctor` counts every record in the last 400 KB of `logs/failures.log` as a failure, and shows each source's last five failures under its name. Before, it kept only records matching the pattern it uses for stderr lines, and the file's last five could push out the log's.
- `scripts/connectome-doctor`'s delivery stage shows a reply that wasn't delivered after the last one that was as not delivered, and one whose delivery the framework couldn't confirm as not confirmed, and makes either a finding. When what it reads holds no delivery, it says the last delivery's time isn't known, and the finding for a reply with no locus gives the framework's line. Before, it took any `[routeSpeech]` line but a no-locus one for a delivery.
- `scripts/connectome-doctor` sends its gate dump's `SIGUSR2` only to a host that has installed its listener, which `/proc/PID/status` shows, so it no longer ends a host that is still starting. `--no-signal` leaves the dump out, and `--data-dir` names a data directory other than `INSTALL_DIR/data`.
- `scripts/connectome-doctor` reads the chronicle ingest stage from the active session's `records.log`, as `sessions.json` names it, and says so when `sessions.json` names none or that session has none; it shows the stage as not known, with the reason, when the index or that `records.log` can't be read, and, with no `sessions.json`, when there are sessions, since which is active isn't known, or the sessions directory can't be listed; and it shows on the forward stage the reason of the last Discord drop discord-mcpl logged within the hour, in its debug log's last 2 MB. Before, it read whichever session's records the directory listed last, and worked out the drop's reason without showing it.
