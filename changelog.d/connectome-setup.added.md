- `bunx @animalabs/connectome-host setup discord`, typed on a terminal in a new directory, sets a resident up on Discord with the host's own setup agent, which talks with the person in that terminal, on `recipes/setup.json`, with `.setup/` as its data directory. Setup starts that agent's host with `CONNECTOME_UPDATE_CHECK=0`, whatever the person's shell sets, so it doesn't check for newer releases on its own: it isn't started through the install's entry point, so it couldn't take one. One setup runs in a directory at a time. Run again, setup goes on where it stopped: once both are answered, it doesn't ask again whether the resident gets a shell or whom it runs as, nor for a key that worked. Setup's last words, once its agent has ended, however it ended, are the install's list of state kept outside the data directory; a run that stops before its agent starts doesn't print it. Before the agent starts, setup:
  - asks whether the resident gets a shell, and whom it runs as. With a shell, on Linux with sudo, the default is a user of its own: setup shows the three root lines that make it, and never runs sudo;
  - checks Bun, 1.4.4 or later, and Node;
  - installs the host at its own version in that directory, with `@animalabs/discord-mcpl`, and `term-sessions-mcp` when the resident gets a shell;
  - makes `./connectome-host` an install that updates when asked, through its host's `/update`, serving `./data`, and writes the install's own `connectome` command in it. Run again on an install, setup keeps to the data directory that install records;
  - boots the installed host on a mock recipe;
  - checks an Anthropic API key with one real call where the agent will make its own, streamed as the agent's are and its answer read by the agent's own client, at the `ANTHROPIC_BASE_URL` in `.env` when it sets one, naming the cause when it fails (a gateway that answers only unstreamed calls fails it), keeps the key in `.env`, and says which model the agent runs on and its prices. An `ANTHROPIC_BASE_URL` exported in the shell that differs from the one in `.env`, or a non-empty one where `.env` sets none, is named, and so is an exported `ANTHROPIC_API_KEY`, empty too, that differs from the key setup checked and keeps in `.env`: setup checks the key with, and gives its agent, what `.env` holds, and says a host started from such a shell takes the exported one.
- A recipe's `modules.setup` gives its agent two tools, in readline mode with stdin and stdout on a terminal only. `setup--run` runs one command with `bash -c` in the install's directory, stopped at a limit. Its environment is the host's, without the stored secrets, the provider credentials the host reads or its providers' base URLs, and no shell startup file is read; a program that reads `.env` itself, as Bun does in that directory, still finds the stored secrets there. Where one of those values appears in the command's output as it was stored, the answer shows the secret's name in its place. `setup--ask_secret` asks the person for a secret with nothing echoed, writes it to `.env` (0600), and answers the agent where it went, never with its value. A `DISCORD_TOKEN`, with any whitespace around it dropped (one that is nothing else isn't stored), is first checked with Discord (`GET /users/@me`, following no redirect), and the person sees on the terminal what came of it, as the agent's answer says: one Discord refuses, or one a request header can't carry (never sent), isn't stored, and what was stored before stays; one Discord accepts is stored and named by its bot; and one it answered otherwise, or couldn't be asked about, is stored as not known to work, with why. `recipes/setup.json` lets its agent use these two and the clock alone.
- Setup and both tools read and write `.env` in one form, which Bun reads as it's written: empty lines, `#` comments, and `NAME=value`, `NAME="value"` or `NAME='value'`, each on one line, `NAME` ASCII letters, digits and `_` and not starting with a digit, with no ASCII control character on any line, no `$`, backslash or quote of its own kind in a quoted value, and none of those, a space, a `#` or any quote in an unquoted one. A `.env` with any other line is refused, naming the first such line by its number alone, and a secret holding a double quote, `$`, backslash or ASCII control character isn't stored.
