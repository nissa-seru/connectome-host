- A server deployed with `mcpl_deploy` now gets the environment every boot-loaded server gets. That includes the refusal-reaction baseline, `DISCORD_SUPPRESSED_REACTIONS_BASELINE`, as a default its own env can override, which a deployed Discord adapter used to start without. `mcpl_deploy` refuses an entry the boot would skip as malformed, such as an `env` that isn't a map, rather than saving it. Numbers and booleans in `env` are saved as their text, as `args` are, and an `env` of `null` means none. `mcpl_unload` reads and writes the overlay with nothing awaited between, so a change landing while a server disconnects is no longer overwritten. A tombstone is recorded even when the disconnect fails. An agent-deployed entry is removed only once its server is gone, so a retried unload can't tombstone the operator's server over it. An id the overlay alone names is unloaded without a disconnect. An id named like `__proto__` is saved as an id, and an inherited name like `toString` is never mistaken for one.
